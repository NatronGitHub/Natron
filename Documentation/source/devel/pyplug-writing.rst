.. _pyplugWriting:

Writing a PyPlug
================

A *PyPlug* is a Python script that re-creates the content of a Group node. Natron registers it as
a plug-in of its own: it appears in the node menus and the tab menu of the node graph, and
:func:`app.createNode()<NatronEngine.App.createNode>` can create it from its plug-in ID. When the
user creates the node, Natron creates a Group node and calls the script to fill it.

The easiest way to make a PyPlug is to build the Group in the user interface and export it
(see :ref:`groups`). This page explains what the exported script contains, how to write one by
hand, and how to distribute it.

.. _pyplugWriting-file:

The PyPlug file
---------------

A PyPlug is a ``.py`` file in one of the :ref:`plug-in search paths<natronPath>` (or one of their
sub-directories). The file name, without ``.py``, is the name of the Python module: it must be a
valid Python module name, so don't use spaces or dashes in it.

Natron reads every ``.py`` file in the search paths at startup, after running the
:ref:`startup scripts<startupScripts>`. A file is taken as a PyPlug if one of its lines starts with
``# Natron PyPlug`` (or with ``# This file was automatically generated by``, as in exported files,
or with ``def createInstance(``). Natron then imports the module and reads these functions:

.. list-table::
   :header-rows: 1
   :widths: 30 15 55

   * - Function
     - Required
     - Returns
   * - ``getLabel()``
     - yes
     - The label shown in the menus, and the default name of new nodes.
   * - ``createInstance(app, group)``
     - yes
     - Nothing. Creates the nodes and parameters inside *group*, the Group node created by Natron
       (see :ref:`below<pyplugWriting-createInstance>`).
   * - ``getPluginID()``
     - no
     - The unique plug-in ID, e.g. ``"fr.inria.groups.MyBlur"``. Defaults to the label.
   * - ``getVersion()``
     - no
     - The major version, an integer. Defaults to 1.
   * - ``getGrouping()``
     - no
     - The menu where the PyPlug appears, e.g. ``"Filter/MyStudio"``. Defaults to ``"Other"``.
   * - ``getPluginDescription()``
     - no
     - The description shown by the **?** button of the settings panel. (``getDescription()``
       is accepted too, for old PyPlugs.)
   * - ``getIconPath()``
     - no
     - The icon file, relative to the directory of the script, e.g. ``"MyBlur.png"``.
   * - ``getIsToolset()``
     - no
     - ``True`` if the file is a :ref:`toolset<pyplugWriting-toolsets>`. Defaults to ``False``.

If the module can't be imported (for example because of a syntax error), Natron writes
*Was not recognized as a PyPlug* and the Python error to the error log
(:menuselection:`Display --> Show Project Errors Log...`). If ``getLabel()`` or
``createInstance()`` is missing, the file is silently ignored. See also :ref:`debuggingPython`.

.. _pyplugWriting-createInstance:

createInstance(app, group)
--------------------------

Natron calls ``createInstance(app, group)`` each time the user creates the PyPlug node, or a
script calls ``app.createNode(pluginID)``. *app* is the :ref:`application instance<App>` and
*group* is the new, empty Group node. The function creates the nodes inside the group, connects
them, and adds the parameters that the user sees on the group.

A group needs an *Input* node for each input and an *Output* node:

- ``fr.inria.built-in.Input`` creates an input of the group. The label of the Input node
  is the input label shown on the node graph.
- ``fr.inria.built-in.Output`` creates the output of the group.

Create the nodes with ``app.createNode(pluginID, -1, group)``, so that they are created
inside *group* and not in the main node graph.

Here is a complete hand-written PyPlug: a blur whose size is controlled by one parameter of the
group. Save it as ``SimpleBlur.py`` in ``~/.Natron`` (or another search path) and restart Natron::

    # Natron PyPlug

    import NatronEngine

    def getPluginID():
        return "org.example.SimpleBlur"

    def getLabel():
        return "SimpleBlur"

    def getVersion():
        return 1

    def getGrouping():
        return "Filter/Examples"

    def getPluginDescription():
        return "Blurs the input. The amount of blur is set by the Size parameter."

    def createInstance(app, group):
        # The user parameters of the group, on a page of their own
        page = group.createPageParam("controls", "Controls")
        size = group.createDoubleParam("blurSize", "Size")
        size.setMinimum(0.)
        size.setDisplayMaximum(100.)
        size.setDefaultValue(10.)
        page.addParam(size)
        group.refreshUserParamsGUI()

        # The nodes inside the group
        source = app.createNode("fr.inria.built-in.Input", -1, group)
        source.setScriptName("Source")
        source.setLabel("Source")
        blur = app.createNode("net.sf.cimg.CImgBlur", -1, group)
        output = app.createNode("fr.inria.built-in.Output", -1, group)

        blur.connectInput(0, source)
        output.connectInput(0, blur)

        # Drive the blur size (both dimensions) from the group parameter
        blur.getParam("size").setExpression("thisGroup.blurSize.get()", False, 0)
        blur.getParam("size").setExpression("thisGroup.blurSize.get()", False, 1)

Then create it from the node menus (:menuselection:`Filter --> Examples --> SimpleBlur`), or with::

    app.createNode("org.example.SimpleBlur")

.. note::

    In expressions inside a PyPlug, refer to the nodes and parameters of the group with the
    ``thisGroup.`` prefix, as above. Without it, the expression looks for a node of the main
    node graph, which doesn't exist in the user's project (see :ref:`paramExpr`).

The PyPlug is **imported** as a module: inside it, only the arguments of ``createInstance``,
the modules it imports, and its own globals are visible. Don't rely on the ``app1`` variables or
on the nodes of the user's project.

.. _pyplugWriting-ext:

Exported PyPlugs and the Ext.py file
------------------------------------

The **Export as PyPlug** button, in the *Node* tab of a Group's settings panel, writes the
Group as a PyPlug. The export dialog asks for the *Unique ID* (returned by ``getPluginID()``),
the *Label* (also used as the file name, ``<Label>.py``), the *Grouping*, the *Version*, an icon and
a description, and the directory to write to. If that directory is not in the search paths, Natron
offers to add it to the "PyPlugs search path" preference.

The exported file starts with ``# DO NOT EDIT THIS FILE``: exporting the Group again overwrites it.
Put hand-written code in a second file, ``<Label>Ext.py``, in the same directory. The exported
script imports everything from it (``from <Label>Ext import *``) if it exists, and its
``createInstance()`` ends by calling ``createInstanceExt(app, group)`` if the Ext module defines it.
Use it to set callbacks, or to change the group after it is built::

    # This is MyPyPlugExt.py, next to MyPyPlug.py

    def paramChangedCallback(thisParam, thisNode, thisGroup, app, userEdited):
        print(thisParam.getScriptName())

    def createInstanceExt(app, group):
        group.onParamChanged.set("MyPyPlug.paramChangedCallback")

A callback defined in a PyPlug is registered with the **module name of the PyPlug** as prefix
(``MyPyPlug.paramChangedCallback``), even when it is defined in the Ext file, because the PyPlug
module imports the content of the Ext module. See :ref:`callbacks` for the signatures.

.. _pyplugWriting-versions:

Plug-in IDs and versions
------------------------

Choose a unique plug-in ID, in reverse domain notation (``org.mystudio.MyEffect``), and keep it
stable: projects store the plug-in ID and the version of each node.

When you change a PyPlug in a way that changes the result of existing projects, increase the
version returned by ``getVersion()`` and keep the old file too. Several versions of the same
plug-in ID can be installed side by side: new nodes use the highest version, and
``app.createNode(pluginID, majorVersion)`` picks a given one. If two files have the same plug-in
ID and version, Natron uses the first one found in the search paths.

.. _pyplugWriting-toolsets:

Toolsets
--------

A toolset is a PyPlug whose ``getIsToolset()`` returns ``True``. Natron doesn't create a Group
node for it: it calls ``createInstance(app, group)`` with ``group`` set to ``None``, and the
function adds nodes to the current node graph, for example a predefined chain of nodes. The *Split and Join* entry of the *Views* menu is a toolset bundled with Natron.
A minimal toolset::

    # Natron PyPlug

    def getPluginID():
        return "org.example.ReadAndBlur"

    def getLabel():
        return "Read and blur"

    def getIsToolset():
        return True

    def createInstance(app, group):
        # group is None for a toolset: create the nodes in the project
        reader = app.createNode("fr.inria.built-in.Read")
        blur = app.createNode("net.sf.cimg.CImgBlur")
        blur.connectInput(0, reader)

.. _pyplugWriting-background:

PyPlugs in background mode
--------------------------

Render farms run NatronRenderer, where the NatronGui module doesn't exist. In background mode,
Natron **skips** every PyPlug file with a line that starts with ``import NatronGui`` or
``from NatronGui import``, so a project that uses such a PyPlug can't be rendered. Keep GUI code
(dialogs, panels) out of the PyPlug: put it in ``initGui.py``, or in a separate module that the
PyPlug only imports inside ``if not NatronEngine.natron.isBackground():``.

.. _pyplugWriting-distribute:

Distributing PyPlugs
--------------------

A PyPlug is a directory with the ``.py`` file, its optional ``Ext.py`` file and its icon. To
install it, copy the directory into a search path: ``~/.Natron`` for one user, the system
location for all the users of a computer, or a shared directory listed in ``NATRON_PLUGIN_PATH``
or in the "PyPlugs search path" preference (see :ref:`natronPath`). PyPlugs are registered at
startup, so restart Natron after installing one.

Since all the directories of the search paths are added to the Python path, a PyPlug can import
Python modules installed next to it.
